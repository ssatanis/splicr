# Lab workspace research and methods export verification

Date: October 8, 2026. Existing user/workspace changes were preserved. No deployment or production database mutation was performed.

## Implemented

- `apps/web/src/lib/report/methods-record.ts` generates a recorded-evidence methods draft. It uses a unique completed `hits` stage, retains unknown versions and parameters, and separates requested configuration, effective parameters and export filtering.
- CSV ZIP exports with Run provenance selected include `methods_text.txt` and `methods-record.json`. Both enter the existing checksum inventory. Omitting provenance omits both files.
- `engine/splicr/pipeline.py` records the effective MLE design/seed, DrugZ options and control-normalisation guide-list checksum/count when those methods ran. Portable reports preserve preceding execution stages with an explicit scope excluding final report completion.
- The research report specifies the unimplemented evidence graph, workspace views, methods, figure bundle and validation programme. These are proposals, not deployed functionality.

## Real-count smoke run

The existing audited Millman study inputs were analysed in a new local work directory with control normalization and MAGeCK RRA. No original study output was overwritten. This used 106,400 guide rows and returned 18,913 target-gene rows in approximately 18.29 seconds on this local environment.

The completed hit stage recorded the checksum and count of the 3,755 negative-control guide IDs actually used for normalization, with MLE and DrugZ parameters correctly absent. The portable report retained the exact hit-stage record. The run reported QC `pass` under its implemented count-table checks and zero discoveries at the configured two-direction FDR threshold. This does not establish physical cell coverage, independent biological replication, or biological validity.

Compact evidence: [lab-methods-smoke.json](lab-methods-smoke.json). Execution log: [lab-methods-smoke.log](lab-methods-smoke.log). Large intermediate files are in the ignored `data/research/lab-workspace-20261008/tools/control-normalization` directory.

Reproduce from the repository root, with the existing audited study inputs and configured local reference/tool environment:

```sh
PATH="$PWD/engine/.tools/env/bin:$PATH" PYTHONPATH=engine \
  OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 \
  engine/.tools/env/bin/python scripts/research/verify_lab_methods_export.py
node scripts/research/export_lab_methods_sample.mjs
```

These commands regenerate only the dedicated smoke output and sample evidence. They are not a clean-platform installation certification. The source engine digest is the digest at execution time, including existing uncommitted engine work.

## Portable sample

It contains all 18,913 gene rows, QC, settings, methods evidence and the existing offline verifier. It is not an export from an authenticated database run and does not assert cloud execution. The bundle is 671,588 bytes and contains ten inventoried payload files plus the manifest. Generation checked every payload size and SHA-256.

Individual downloads: [sample-methods_text.txt](sample-methods_text.txt) and [sample-methods-record.json](sample-methods-record.json). Tool versions/container digest remain unknown in this sample because the relevant execution metadata did not record them. No versions were copied from intended installation pins.

Extract the ZIP and run `python3 verify-bundle.py` to check listed bytes. Checksums do not authenticate the manifest, establish authorship, or validate scientific conclusions. This sample exercises methods/provenance export, not the proposed full paper bundle with standalone figures, notebooks and discussion snapshots.
